## Види NoSQL баз

- key-value (Redis) - кеш, сесії, лічильники
- документні (MongoDB) - дані у вигляді JSON-документів
- колонкові (Cassandra) - багато записів, логи
- графові (Neo4j) - зв'язки між об'єктами
- часові ряди (InfluxDB) - метрики

## Що винесла в NoSQL

Основні дані (розклад, оцінки, довідники) залишила в PostgreSQL, бо там потрібні зв'язки і транзакції.

В MongoDB винесла профіль студента: дані студента, група, факультет, оцінки, середній бал і досягнення. У SQL для профілю треба з'єднувати 12 таблиць, а в MongoDB це один документ. Профіль часто читають, а оцінки ставлять рідше.

Додала нову вимогу: портфоліо досягнень (олімпіади, сертифікати, публікації). У різних досягнень різні поля, тому в SQL для кожного типу окрема таблиця, а в MongoDB просто різні поля в масиві.

Мінус: назва дисципліни зберігається в кожному документі, тому якщо її змінити, треба оновлювати багато документів.

В Redis - кеш профілів і рейтинг студентів.

## Тестування швидкодії

`benchmark.py` генерує однакові дані в обох базах і запускає тести на 10000, 50000 і 100000 студентах (по 30 оцінок).

Тести:
- T1 - профіль студента за id
- T2 - профілі всієї групи
- T3 - додати оцінку
- T4 - перейменувати дисципліну
- T5 - середній бал по кожній дисципліні
- T6 - переможці міжнародних олімпіад
- T7 - топ-20 студентів факультету

Для всіх баз однакові випадкові id, є індекси, перед тестом прогрів. Записи в MongoDB з `j: true`, щоб чекати запису на диск як у PostgreSQL. Беру медіану, бо середнє псують випадкові затримки.

Результати для 100000 студентів (медіана, мс):

| Тест | SQL (3 запити) | SQL (1 запит) | JSONB | MongoDB |
|---|---|---|---|---|
| T1 | 5.41 | 3.54 | 0.90 | 1.49 |
| T2 | 20.03 | 17.55 | 3.10 | 3.77 |
| T3 | 0.27 | - | 0.58 | 1.68 |
| T4 | 0.55 | - | 44468 | 2215 |
| T5 | 162 | - | 639 | 1419 |
| T6 | 2.61 | - | 5.96 | 1.96 |
| T7 | 224 | - | 0.84 | 1.58 |

Розмір: SQL 377 МБ, JSONB 401 МБ, MongoDB 149 МБ.

Графіки і всі результати в папках `results`  `screenshots` 

Що вийшло:
- читання профілю (T1, T2) з документа в кілька разів швидше, бо немає join
- додати оцінку (T3) швидше в SQL
- перейменування дисципліни (T4) в SQL займає 1 мс, а в MongoDB 2 с, бо змінюється половина документів. JSONB ще повільніший, бо переписує весь документ
- звіт по всіх оцінках (T5) швидше в SQL
- пошук по індексу (T6) скрізь швидкий
- топ факультету (T7) в документах швидкий, бо середній бал вже збережений, а в SQL рахується кожен раз
- MongoDB займає менше місця через стиснення

MongoDB і Redis запускались у Docker, PostgreSQL напряму, тому MongoDB трохи програє на дрібних запитах.

## Redis

В `redis_lab/redis_commands.txt` базові команди: string, hash, list, set, sorted set, TTL, MULTI.

В `redis_lab/redis_demo.py` кеш профілю, рейтинг факультету через sorted set і порівняння швидкості читання.

## Висновок

Всю базу переносити в MongoDB немає сенсу. Але профіль студента в MongoDB читається швидше і в нього легко додавати нові поля. Зміни довідників і звіти краще робити в SQL. Redis зручний для кешу і рейтингів.
